**Важные уроки по картинкам (не наступать снова):**

- Кол-во фото в ротации намеренно урезано (5 шт для fullscreen) ради веса —

- Кол-во слайдов в наборе завязано на % в keyframes (`100/N`). Если меняешь длину

- Картинки хотлинкаются напрямую с `images.unsplash.com` — это НЕ грузит наш
  Vercel/сервер, трафик идёт у пользователя в браузере напрямую с CDN Unsplash.

## Бэкенд-архитектура (2026-08-24)

**Важно: прокси `api.vibecode-claude.online` — это НЕ баг и не костыль.** Это
единственный сейчас способ платить за доступ к Claude из России (нет карты для
официального `api.anthropic.com`). Любые будущие изменения не должны исходить
из «просто переключить на официальный API» — база URL и модель нарочно вынесены
в конфиг, чтобы провайдера можно было сменить без правки кода, но по умолчанию
всегда прокси.

### Общий AI-клиент — `lib/ai.ts`
Единая точка входа для всех вызовов Claude: `askAI(prompt, opts)` +
`extractJson(text)`. Конфигурируется из `ANTHROPIC_API_KEY` / `ANTHROPIC_BASE_URL`
/ `ANTHROPIC_MODEL` — нигде в коде эти значения не хардкодятся. Любой новый
AI-фичер (например, будущий SoP-ассистент) должен переиспользовать эти же две
функции, а не заводить свой `new Anthropic(...)`.

`app/api/verdict/route.ts` использует этот клиент и оборачивает вызов в
try/catch — при ошибке (например, `insufficient_credits`) возвращает чистый
JSON `{error}` с кодом 502 вместо пустого 500.

Подтверждено прямым тестом: прокси принимает имя модели `claude-sonnet-4.6`
(ошибка была именно про баланс — `403 insufficient_credits` — а не про
неизвестную модель). Баланс на аккаунте прокси нужно пополнить, чтобы кнопка
«Персональный анализ» в дашборде и наполнение базы вузов заработали.

### Service-role доступ — `lib/supabaseAdmin.ts`
Второй Supabase-клиент, отдельный от `lib/supabase.ts` (anon key). Использует
`SUPABASE_SERVICE_ROLE_KEY` (секрет из Supabase Dashboard → Settings → API →
`service_role`) и нужен только для серверных операций записи, которые не
разрешены анонимному ключу по текущим RLS-политикам (`universities`/`programs`
дают анону только `SELECT`). Инициализация ленивая (`getSupabaseAdmin()`) —
специально, чтобы отсутствие ключа не ломало сборку, только конкретный запрос.
**Никогда не импортировать этот клиент в клиентские компоненты.**

### Автонаполнение базы — `app/api/admin/seed-programs/route.ts`
Заменяет `app/dashboard/fill_db.py` (логика 1:1 перенесена на TypeScript, тот
же перебор 20 стран × 8 направлений с проверкой на дубли). Отличия:
- Требует заголовок `Authorization: Bearer $CRON_SECRET` — так Vercel Cron
  сам подписывает запросы, когда задан `CRON_SECRET`, без кастомной схемы.
- `?country=de&field=Computer%20Science` — ручной прогон одной комбинации
  (для теста через curl/браузер с секретом).
- Без параметров — весь список сразу, но с бюджетом по времени (`maxDuration=60`,
  внутренний cutoff 50с) — обрабатывает сколько успевает и возвращает
  `stoppedEarly: true`, если не уложился. Раз уже обработанные комбинации
  пропускаются мгновенно (дедуп-проверка), после первого полного прогона
  еженедельный cron будет обрабатывать только новые страны/направления и
  укладываться быстро.
- Расписание — `vercel.json` в корне, по умолчанию понедельник 03:00 UTC.

**`fill_db.py` пока НЕ удалён** — по плану он удаляется только после того, как
новый роут подтверждённо отработает end-to-end (нужны реальный
`SUPABASE_SERVICE_ROLE_KEY` и баланс на прокси, которых пока нет). Не удалять
раньше, чем реально протестирован.

### Заложено на будущее, но не реализовано
Паттерн общий для всех — используем `askAI`/`extractJson` из `lib/ai.ts`, ничего
нового изобретать не нужно:
- **SoP-ассистент**: `app/api/sop-draft/route.ts`, по образцу `verdict/route.ts`.
- **PDF-экспорт шортлиста**: чисто клиентский код (например `@react-pdf/renderer`),
  бэкенд не нужен.
- **Аналитика (Posthog)**: клиентский скрипт + `NEXT_PUBLIC_POSTHOG_KEY`,
  без кастомного бэкенда.
- **SEO-страницы программ** (`app/program/[id]/page.tsx`): серverкомпонент,
  читает напрямую через `lib/supabase.ts`, статика/ISR — новый бэкенд не нужен.

## Честность данных (2026-08-24)

Прямая проверка живой базы (281 программа, 117 вузов) нашла реальный баг:
у ~30 программ (`field = 'Computer Science / AI'` или `'Engineering'`) значение
не совпадает ни с одним значением, по которому фронтенд фильтрует программы —
эти строки никогда не показывались ни одному студенту. SQL-фикс подготовлен и
передан Денису для самостоятельного запуска в Supabase SQL Editor (там же
добавляется колонка `programs.verified boolean` + `verified_at`).

**Колонка `verified`**: `false`/`null` по умолчанию — значит данные программы
сгенерированы ИИ и не проверены человеком. `true` — проверено вручную против
официального сайта вуза. UI показывает бейдж `VerifiedBadge` (в
`dashboard/page.tsx`) везде, где отображается программа: список, модалка,
таблица сравнения.

**GanttTimeline.tsx / Timeline.tsx** теперь принимают проп `programs` (реальные
избранные/подобранные программы с `deadline_month`/`deadline_day`/`url` из БД)
вместо старых захардкоженных «одна дата на страну» словарей. Если когда-нибудь
понадобится что-то похожее — **никогда не хардкодить даты в компоненте**,
всегда брать из переданных программ.

**Timeline.tsx экспортируется, но нигде не рендерится** в `dashboard/page.tsx`
(на вкладке «Таймлайн» используется только `GanttTimeline`) — обнаружено при
этой правке, похоже на мёртвый код или недоделанный свитч между двумя
вариантами таймлайна. Не трогал, просто фиксирую факт.

## Авторизация (2026-08-24, вторая правка)

Было 3 реальные проблемы, все нашёл и починил:

1. **`app/page.tsx` никогда не проверял сессию** — залогиненный пользователь,
   зайдя на `/`, всегда видел онбординг с нуля. Добавлена проверка сессии на
   маунте → редирект на `/dashboard`, как это уже было сделано в `/login`.
2. **Не было кнопки «Войти»** на лендинге — теперь ссылка на `/login` в шапке
   hero (там, где раньше была фейковая цифра про 2400 студентов).
3. **Магическая ссылка на email ломалась при открытии на другом устройстве**
   (типичный случай: анкету заполнили на ноуте, почту открыли на телефоне).
   Анкета сохранялась только в `localStorage` — на другом устройстве его
   попросту нет, профиль не находился, и `dashboard/page.tsx` кидал на `/`.
   Плюс сам экран после отправки ссылки был сломан — ошибочно переиспользовал
   анимацию «строим план» (see `step===99` in `app/page.tsx`), которая через
   3.5с сама возвращает на экран результата — выглядело как "ничего не
   произошло". Теперь: (а) есть отдельный экран-подтверждение «Проверь почту»
   (`emailSent` state), (б) анкета дублируется в новую таблицу
   `pending_profiles` (ключ — email, а не user_id, потому что до входа
   user_id ещё не существует), и `dashboard/page.tsx` при отсутствии профиля
   по `user_id` ищет черновик по `session.user.email` перед тем как сдаться
   и отправить на `/`.

**Таблица `pending_profiles`** нужна и на вход (перед авторизацией, аноним
пишет через `upsert`), и на чтение (уже авторизованный пользователь ищет свой
черновик по email) — поэтому RLS отдельно разрешает insert/update всем, а
select/delete только когда `auth.jwt() ->> 'email' = email`.

## Вход по паролю (2026-08-24, третья правка)

Добавлен как ТРЕТИЙ вариант входа, ничего не убрано — Google и ссылка на почту
работают как раньше.

- **`lib/useTurnstile.ts`** — общий hook для капчи Cloudflare Turnstile. Если
  `NEXT_PUBLIC_TURNSTILE_SITE_KEY` пуст — просто не рендерит виджет и не
  добавляет `captchaToken` в запросы (ничего не ломается). Используется и в
  `app/login/page.tsx`, и в `app/page.tsx` (шаг 8, если ввели пароль).
- **`app/login/page.tsx`** — переключатель «Ссылка на почту» / «Пароль» с
  режимами Войти / Регистрация / Забыли пароль внутри.
- **`app/reset-password/page.tsx`** (новый) — страница, куда ведёт письмо
  сброса пароля; слушает событие `PASSWORD_RECOVERY` от Supabase.
- **`app/page.tsx` шаг 8** — email-поле осталось, добавлено необязательное
  поле пароля. Если заполнено — `signUp` вместо `signInWithOtp`. В обоих
  случаях анкета всё равно уходит в `pending_profiles` (см. выше) — работает
  независимо от того, каким методом в итоге входят.

**Важно про порядок включения защиты** — если сделать не по порядку, сломаешь
уже работающий вход:

1. Создай Turnstile-виджет в Cloudflare Dashboard → Turnstile (у тебя уже
   есть аккаунт Cloudflare под DNS mastersly.ru). Получишь Site Key (публичный)
   и Secret Key (приватный).
2. Site Key — пришли мне или впиши сам в `.env.local` и в Vercel как
   `NEXT_PUBLIC_TURNSTILE_SITE_KEY`.
3. Secret Key — вставь в Supabase Dashboard → Authentication → Settings →
   "Enable CAPTCHA protection" → провайдер Turnstile.
4. **Только после того как задеплоено и Site Key уже отдаётся с сайта** —
   включай "Enable CAPTCHA protection" в Supabase. Если включить раньше, чем
   виджет реально появится на сайте — вход/регистрация начнут падать с
   ошибкой "captcha verification failed", включая уже работающую ссылку на
   почту при онбординге.
5. Отдельно, когда будет готово: Supabase Dashboard → Authentication →
   Providers → Email → "Confirm email" (ON) — обязательное подтверждение
   почты перед входом по паролю. Это тоже настройка, не код.

## Локальный дев-сервер

`.env.local` заполнен: Supabase URL/anon key, `ANTHROPIC_API_KEY`/`ANTHROPIC_BASE_URL`/
`ANTHROPIC_MODEL` (прокси), `CRON_SECRET` (сгенерирован). `SUPABASE_SERVICE_ROLE_KEY`
пока пустой — нужно вставить вручную из Supabase Dashboard, когда будет тестироваться
`seed-programs`. Те же переменные должны быть добавлены в Vercel (Settings →
Environment Variables), иначе прод-версия эндпоинтов будет падать так же, как
локально без ключа.
`.claude/launch.json` в `C:\Users\kulya\.claude\` настроен на
`npm --prefix <путь> run dev`, порт 3000.

```bash
npm install         # если node_modules нет
npm run dev          # http://localhost:3000
npm run build         # прод-сборка, обязательно проверять перед пушем
npx tsc --noEmit      # быстрый тайпчек без полной сборки
```

При смене шрифтов/next-font иногда залипает кэш Turbopack — если после правки
шрифтов что-то не применяется, `rm -rf .next` и рестарт дев-сервера.
